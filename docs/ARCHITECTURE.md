# 执行状态与工具契约

本项目使用 LangGraph 的 `StateGraph`；业务工具和模型适配层为独立实现。

## 状态

| 字段 | 含义 |
|---|---|
| messages | 本次任务完整消息序列，含模型工具请求及对应结果 |
| rounds / tool_count | 已完成的模型响应轮数 / 已执行工具数 |
| evidence | read_file 实际返回的片段、行号和整文件哈希 |
| trace | 节点耗时、工具状态、服务端 usage；不存原始异常字符串 |
| answer | 最终回答或停止提示 |
| stop_reason | completed、invalid_citations、empty_response、model_error、max_rounds、max_tools |
| citation_errors | 无法由本次读取记录支持的标准引用 |

状态列表由节点返回完整的新列表，当前图为串行单分支，不需要并行合并 reducer。没有持久化 checkpointer；进程退出后只能查看手动保存的 JSON 记录，不能从记录恢复执行。

## 路由与预算

模型无工具请求时结束；返回工具请求且预算允许时进入工具节点。单次响应中的工具按顺序执行，每个 call ID 均对应一条工具响应。工具预算不够时整批不执行；轮数预算到达后不再调用模型。LangGraph 的 recursion_limit 是额外保护，显式业务预算负责产生易读的停止原因。

模型调用失败或超时结束任务；工具参数错误或访问失败会作为结构化结果回传给模型，它可以纠正参数或解释无法完成。工具访问为同步文件操作，在工作线程运行，有扫描量和大小限制，但不提供对卡住的网络文件系统的硬取消能力。

## 工具

输入是仓库相对路径，统一使用 `/`。只注册三个工具，没有 Shell、Python 执行、浏览器、任意文件写入能力。

- `list_files(path='.', limit=100)`：递归列出允许后缀的源码文件，最多返回 500 个文件，最多检查 10000 个目录项；过滤目录和链接，存在截断时标记。
- `search_code(query, path='.', limit=30)`：区分大小写的字面量搜索，最多扫描 500 个候选文件，最多返回 100 个匹配，单行摘要最多 500 字符。大文件、二进制、非 UTF-8 文件跳过并计数。
- `read_file(path, start=1, end=80)`：文件最多 256000 字节，最多 120 行、12000 字符。不截断单行后声称已读取完整行；首行超长时返回错误。

工具返回 `{ok: true, data: ...}` 或 `{ok: false, error: code}`。搜索摘要不是可引用证据，需要进一步读取文件。

## 引用与可信度

仅解析 `[[相对路径:L起始行-L结束行]]` 标准格式。每个引用必须完全包含于一个实际 read_file 片段。校验依据是当时的读取快照而非稍后的磁盘内容；哈希用于标识文件版本。

这不证明引用与文字结论语义相符，也不会检测普通文字中所有伪装的引用。`completed` 表示流程正常结束，不表示答案质量通过人工评测。无引用回答可用于说明证据不足，暂未强制每个断言关联引用。

## 当前取舍

不为第一版引入数据库、索引和 API 服务；先验证工具链路和真实模型能力。后续加入多分支时需要重新设计状态合并规则，加入恢复功能时需要持久化检查点与副作用幂等性设计。
